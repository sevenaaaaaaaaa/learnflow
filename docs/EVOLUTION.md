# LearnFlow · 自我进化与迭代（EVOLUTION.md）

> 目标：像 OpenFlow 那样，让 LearnFlow 能**自我体检 → 生成改进提案 → （护栏内）执行动作 → 验证效果 → 沉淀记忆**，持续迭代，而不是靠人肉发现和重写。

## 一、设计来源（对齐 OpenFlow）

借鉴 OpenFlow 的四件套，按同一原则裁剪：

| OpenFlow | LearnFlow 对应 | 说明 |
|---|---|---|
| `SelfEvolve`（自体检→结构化建议） | `lib/SelfEvolve.php` + `/admin/evolution.php` | 聚合工程/内容/运营/业务信号，产出提案清单 |
| `AutonomyGuard`（三级自治） | 同样的三级：`propose / guarded / goal` | 低风险自动、高风险人工确认、预算+频控 |
| `DecisionTrace`（决策可回溯） | 决策记录入 `evolution.json` | 每条提案有输入、动作、结果、状态 |
| `GrowthMemory`（策略复利） | 策略库（采纳→效果） | 有效策略沉淀复用 |

**硬边界**：发钱（券/佣金/退款）、群发、改价、发布——**任何级别都需人工确认**。

## 二、信号层（进化输入）

1. **工程**：`php-error.log` 近期错误、慢页、空模块、备份是否及时、`data/` 体积
2. **内容**：课时流失偏高、题目正确率偏低、AI 答疑未命中、课程内容缺口（无课时/空正文）
3. **运营**：风险学员、作业未批改、打卡停滞、直播未排期
4. **业务**：漏斗转化、近 N 天无付费、复购率、退款（经 PayFlow）
5. **外部（矩阵 API）**：inFlow 选题/舆情、UserLoop 旅程断点、PayFlow 订单、MFlow 内容表现

## 三、执行层（Ops Loop）

```
信号 → 提案(propose) → 人工/护栏判定 → 执行(act) → 验证(verify) → 记忆(memory)
```

可执行动作（经内部能力或矩阵 MCP/API）：
- 内容：生成/改写课时讲义、补大纲、生成招生/社群/直播文案
- 运营：给风险学员发提醒（→ UserLoop 触达）、催交作业、排直播
- 转化：建议并生成优惠券 / 推荐活动（券核销在 LearnFlow，收款在 PayFlow）
- 工程：开改进单（补页面/修 bug 提示）

## 四、自治分级（AutonomyGuard）

| 级别 | 行为 | 适用 |
|---|---|---|
| **L0 propose**（默认） | 只提议，人工执行 | 全部动作，起步阶段 |
| **L1 guarded** | 护栏内自动：仅**低风险**动作（生成草稿、发学习提醒、出周报），受预算/频控/静默期约束 | 熟练后逐步放开单条工作流 |
| **L2 goal** | 给目标+预算，护栏内自主决策（仍不碰高风险） | 有稳定策略后 |

- 按**单条工作流**提升自治，不设全局“全自动”开关
- AI 不可用时：Flow 完整可用，Loop 保留状态并明确降级

## 五、迭代路线

- **E0 自体检（已落地）**：`SelfEvolve` 聚合信号 → 提案清单；后台「自进化」页可运行体检、采纳/解决、让 AI 给改进建议；cron 每日体检
- **E1 动作闭环（已落地）**：提案携带**可执行动作**（生成课时讲义 / 生成营销草稿 / 向风险学员发提醒 / 生成优化建议），**人工点「执行」**后执行并记录结果；**下次体检信号消失即自动标记「已验证」**（executed→verified）
- **E2 分级自治**：L1 低风险自动（补内容草稿/发提醒/周报），预算与频控兜底
- **E3 策略复利**：策略库 + 效果回流 + A/B，形成「越用越准」

## 六、成功标准（可度量）

- 提案**采纳率**、**闭环率**（提案→动作→验证）
- 关键指标改善：完课率、复购/付费转化、风险学员召回、内容/出题耗时
- 每次 Loop 运行有**输入/证据/步骤/成本/审批/输出/结果**记录
- 回归不下降；所有进化动作**可独立关闭与回退**

## 七、与矩阵的关系

- **信号**可来自 UserLoop/inFlow/PayFlow/MFlow 的 API（如旅程断点、选题热度、订单）
- **动作**可经各产品 MCP/API 执行（如让 UserLoop 做触达、让 MFlow 做分发）
- LearnFlow 只做「课程交付 + 内容工作台 + 进化编排」，不与其它产品争职责
